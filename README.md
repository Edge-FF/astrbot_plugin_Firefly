# 流萤认知外壳

> `astrbot_plugin_Firefly` · v0.3.0

给 AstrBot 里的角色扮演装上一套**「认知外壳」**：一份稳定的人格、会自己变化的心情、能记住的上下文，以及由心情驱动的主动找你。

装好之后，你的角色不再只是"每次重新读一遍人设"，而是**带着当前心情、想着最近聊过的事、在需要时才翻出对应资料**来和你说话。

## 主要功能

### 1. 人格外壳注入

每次向模型发起请求前，插件会自动把角色的「认知外壳」拼进上下文，包含三部分：

| 部分 | 内容 | 是否常驻 |
|---|---|---|
| **静止设定** | 角色是谁——人格、经历、价值观、行为习惯 | ✅ 每次都在 |
| **用户身份** | 正在和你对话的人是谁（预设角色） | ✅ 每次都在（选了身份时） |
| **动态状态** | 当前心情 + 最近聊过的话题 | ✅ 每次都在 |
| **激活资料** | 当前场景相关的技能、人物关系、世界观 | 按需注入 |

外壳会自动去重、按 token 预算裁剪，并在超预算时告警。

### 2. 分层资料 + 按需激活

角色的设定不用一股脑全塞给模型。插件把它们分成四层：

- **Tier 1（常驻）**：核心人格、自我叙事——永远在场
- **Tier 3（按需）**：技能、人物关系——聊到相关话题才激活
- **Tier 4（按需）**：世界观、故事背景——同上

被激活的资料不会立刻消失，而是带**惯性**：逐轮衰减，聊着聊着自然淡出。这让"她刚刚提到过的东西"不会瞬间忘掉。

### 3. 情绪系统

角色有一份会变化的心情，共 9 种：**平静 / 开心 / 难过 / 生气 / 疲惫 / 惊喜 / 想念 / 委屈 / 心疼**。

关键区别：**心情是"她的反应"，不是"复读你的情绪"。**

| 你说的话 | 她的反应 |
|---|---|
| 你很难过 | 她**心疼** |
| 你凶她 | 她**委屈** |
| 你亲昵 | 她**开心** |
| 你很久没来 | 她**想念** |

心情会随时间自然衰减（各有半衰期），也会被她自己的经历影响（比如她主动找你而你没回）。

### 4. 主动消息（默认关闭）

角色可以**在你没说话时主动找你**——但她不是"定时器到点就发"，而是由**冲动值**决定：

```
冲动值 = 静默时长 × 心情倾向 + 未回复次数 × 加成
```

心情倾向决定她多沉不住气（想念最快、生气时反而抑制），未回复次数让她更容易再开口。同时有一整套防打扰机制：免打扰时段、最短间隔、未回复上限、每日上限、启动宽限、每次最多发几条。

### 5. 定时任务与提醒

配合 AstrBot 内置的定时任务系统使用时，**任务的执行也会带上她的认知外壳**——也就是说，到点提醒你的那句话，是她用**自己的语气**说的，而不是冷冰冰的系统播报。

同时，任务触发**不会扰乱她的心情**（不会被误判成"你回复了她"）。

### 6. 可视化调试

AstrBot 插件页面提供调试面板，用来观察并调整她的运行状态。面板跟随 Dashboard 的明暗主题，共 7 个 Tab：

| Tab | 内容 |
|---|---|
| **注入日志** | 每次注入的完整外壳内容、路由命中了哪些资料、跳过原因、Token 预算 |
| **状态面板** | 当前会话的心情、最近话题、激活上下文（可手动激活 / 停用条目、重置会话） |
| **路由测试** | 输入一句话，看它会命中哪些资料、走 LLM 还是关键词路由 |
| **资料浏览** | 两栏资料管理器：左栏目录树（搜索 / 层级筛选 / 状态标记），右栏编辑器 |
| **用户角色** | 选择"你"的身份：现有人物或自定义角色，并预览真实注入正文 |
| **注入预览** | 模拟一条消息，预览将要注入的内容与预算占用 |
| **系统统计** | 累计注入次数、路由占比、当前配置 |

**资料可以直接在面板里编辑**（只作用于 `role/` 下的 `.md` 文件）：

- 编辑器有三种模式：**表单**（结构化字段 + 标签输入）、**预览**（Markdown 渲染）、**原始全文**（直接编辑整份文件）。
- 保存由服务端重新解析并规范化 front-matter（未识别的键原样保留）；带 `rev` 乐观锁，文件被外部改动时会提示重新加载。
- 支持**重命名 / 移动**（不改变文件内容与 `rev`）与**硬删除**（需输入文件名确认；若该条目正被会话激活，还要额外勾选确认）。
- 保存 / 重命名 / 删除后**自动重载资料**，不需要再执行 `/firefly reload`。

## 亮点

- **零第三方依赖**：只用 AstrBot 接口与标准库，装完即用，不需要额外 `pip install`。
- **不修改 AstrBot 主程序**：纯插件实现，AstrBot 升级不必担心被覆盖。
- **Token 友好**：分层 + 按需激活 + LRU 缓存 + 预算裁剪，长人设也不会把上下文撑爆。
- **情绪不是复读机**：用户情绪只作为"输入信号"，她的心情由自己的反应规则决定。
- **主动但不烦人**：由状态驱动而非定时器，并且有六重防打扰保护。
- **资料是纯 Markdown**：用 front-matter 描述元数据，非程序员也能写。
- **完整可观测**：每一步"注入了什么、为什么没注入"都能在面板里查到。

## 快速开始

### 第 1 步：安装

把插件目录放到 AstrBot 的插件目录下，然后在 AstrBot 的插件页面重载（或重启 AstrBot）：

```
AstrBot/data/plugins/astrbot_plugin_Firefly/
```

### 第 2 步：确认生效

插件**默认已启用**（`enabled = true`）。发一条消息，然后在插件页面的调试面板里应该能看到注入记录。

也可以直接用命令查看：

```
/firefly status
```

### 第 3 步（可选）：换成你自己的角色

把 `role/` 目录里的资料换成你要扮演的角色设定，详见下一节。

### 第 4 步（可选）：开启主动消息

主动消息**默认关闭**，需要手动开启：

```
/firefly proactive on
```

或在插件配置里把 `proactive.enabled` 设为 `true`。建议先只在 `proactive.sessions` 里填一个测试会话，确认手感后再放开。

## 资料体系：把人设换成你自己的角色

### 目录约定

`role/` 目录下的文件会按**目录与文件名**自动分层，你只要放对位置即可：

| 位置 | 层级 | 作用 |
|---|---|---|
| `role/基础人设.md` | Tier 1 常驻 | 角色是谁（核心人格） |
| `role/故事/` | Tier 1 常驻 | 自我叙事、经历 |
| `role/技能/` | Tier 3 按需 | 能力、习惯、喜好 |
| `role/人物关系/` | Tier 3 按需 | 与各个角色的关系 |
| `role/世界知识/` | Tier 4 按需 | 世界观、派系、背景 |

> 放在 `role/` 根目录的其它 `.md` 默认也会当作 Tier 1 常驻；子目录默认 Tier 3。

### 文件格式

每个资料文件 = **front-matter 元数据** + **正文**：

```markdown
---
type: on_demand          # static=常驻；on_demand=按需激活
kind: skill              # persona / skill / lore / narrative
title: 机甲战斗模式
id: skill_battle
keywords: ["战斗", "打架", "机甲"]   # on_demand 时用于触发激活
priority: 60
default_ttl: 4           # 激活后保持几轮
---

正文写这个条目的具体内容……
```

**字段说明**

| 字段 | 必填 | 说明 |
|---|---|---|
| `type` | 建议 | `static` 常驻；`on_demand` 按关键词激活 |
| `kind` | 建议 | `persona` / `skill` / `lore` / `narrative` |
| `title` | 建议 | 条目名称（显示在调试面板） |
| `id` | 建议 | 唯一标识，缺省会按文件名生成 |
| `keywords` | 按需 | 按需条目被激活的触发词 |
| `tier` | 可选 | 手动指定层级，覆盖目录推断 |
| `priority` | 可选 | 同层排序优先级 |
| `default_ttl` | 可选 | 激活后保持的轮数 |

### 写作建议

- **核心人格写细一点**：它常驻，是角色稳定性的地基。
- **技能/世界观用关键词**：写得越贴近你的聊天习惯，激活越准。
- **不要把所有东西都设成常驻**：常驻越多，token 消耗越大，模型的注意力也越分散。
- **一个文件一个主题**：便于按需激活与单独调试。

## 用户角色预设

她需要知道**正在和她对话的人是谁**。用户角色预设就是"你是以什么身份和她说话"。

有两种选择：

| 选择 | 效果 |
|---|---|
| **现有角色**（默认开拓者） | 复用 `role/人物关系/` 里的人物资料作为你的身份，每次对话常驻注入 |
| **自定义角色** | 新建一份只属于"你"的设定文档，作为你的身份常驻注入 |

### 关键点：选身份 = "钉选"，不是替换或删除

- 无论选哪种，**没有任何资料文件会被移动、改写或删除**。
- 选定某份文档作为身份后，它会被**常驻注入**，并在该会话中**暂时从"按需激活"里排除**（避免同一段内容注入两遍）。
- 选自定义角色时，`role/人物关系/开拓者.md` 会**退回成一号普通人物资料，照常按需触发**——她依然"认识"开拓者，只是那不再是你。

### 三种设置入口

| 入口 | 作用范围 | 说明 |
|---|---|---|
| 调试面板 **「用户角色」Tab** | 全局默认 | 左栏二选一（现有 / 自定义）+ 搜索，右栏预览真实注入正文；可新建 / 编辑 / 删除自定义角色 |
| `/firefly role ...` 命令 | 仅当前会话 | 会话级覆盖，优先于全局默认（适合一个 bot 服务多个人的场景） |
| `role/用户角色/*.md` 文件 | — | 自定义角色的存储位置，也可直接用「资料浏览」编辑 |

### 自定义角色文档

放在 `role/用户角色/` 下，普通 `.md` + front-matter 即可：

```markdown
---
id: my_role
title: 我的角色
kind: user_role
---

我是一个……（描述这个角色是谁、与流萤的关系、对话时的定位）
```

注意事项：

- `id` 是身份的主键，必须全局唯一；**改名会让 id 变化、从而解除绑定**，面板里的编辑因此把文件名与 id 设为只读。
- **正文不能为空**：空文档不能作为身份（面板会禁选，命令与接口会拒绝）。
- 自定义角色文档**永远不会进入按需路由**，不会泄露给其它会话。
- 身份块默认上限 600 token（`user_role.user_profile_max_tokens`），超长会截断自身，不影响其它资料。

## 主动消息

### 她什么时候会主动找你

不是定时器，而是"越想你越想找你"：

- 静默越久 → 冲动值越高
- 心情不同 → 增长速度不同（**想念**最快、**生气**时被抑制）
- 她找过你但你没回 → 冲动值进一步上升

当冲动值越过当前心情的阈值、且通过全部保护闸门时，她才会开口。

### 六重防打扰

| 机制 | 默认 |
|---|---|
| 免打扰时段 | `1-7`（凌晨 1 点到 7 点） |
| 距上次接触的最短静默 | 30 分钟 |
| 两次主动的最小间隔 | 60 分钟 |
| 连续未回复上限 | 4 次（达到后暂停） |
| 每日上限 | 6 次 |
| 启动宽限期 | 120 秒 |

另外还有一个**"你别说话她就安静"**的保护：她开始生成消息时如果你刚好发言，这条主动消息会被丢弃。

### 开发中会用到的手感调节

| 想要的效果 | 调哪里 |
|---|---|
| 她更黏人 / 更冷淡 | `role/` 里的人格写法 + 心情倾向（需改代码常量） |
| 她多久才会想找你 | `min_contact_gap_minutes`、`min_proactive_interval_minutes` |
| 静默多久开始想念 | `silence_hours`（默认 6 小时） |
| 别太频繁 | `max_per_day`、`max_unanswered`、`max_sends_per_tick` |
| 免打扰时段 | `quiet_hours`（支持跨天，如 `23-6`） |

## 定时任务与提醒

AstrBot 自带定时任务能力（内置的 `future_task` 工具），你可以直接对话让她建任务：

> 一小时后提醒我取快递
> 明早八点叫我起床
> 每天中午提醒我吃药

**本插件的增强**：任务到点执行时，会把她的认知外壳一并注入，因此那句提醒会带上她的人格与当前心情，而不是通用助手腔。

同时，任务触发**不会污染她的情绪状态**——不会被误算成"你回复了她"，也不会把提醒内容当成你说的话。

> 提示：该能力依赖 AstrBot 的内置任务系统与 `on_agent_begin` 钩子。若你的 AstrBot 版本较旧，任务提醒仍可用，只是可能不带外壳，插件会自动降级、不会报错。

## 命令

所有命令都需要 **AstrBot 管理员权限**。

| 命令 | 作用 |
|---|---|
| `/firefly status` | 查看插件状态：资料数量、各层统计、当前配置要点 |
| `/firefly state [会话]` | 查看指定会话的动态状态（心情、话题、激活资料） |
| `/firefly reset` | 重置当前会话的动态状态 |
| `/firefly reload` | 重新加载 `role/` 资料（手动改文件后用；在面板里保存会自动重载） |
| `/firefly proactive on\|off` | 运行时开启 / 关闭主动消息 |
| `/firefly proactive status` | 查看各会话的冲动值与闸门状态 |
| `/firefly proactive now [会话]` | 立即手动触发一次主动消息（用于测试） |
| `/firefly role` | 查看全局默认与本会话的用户身份（同 `role status`） |
| `/firefly role set existing [id]` | 本会话身份设为某个现有人物（省略 id = 内置默认开拓者） |
| `/firefly role set custom <id>` | 本会话身份设为某个自定义角色文档 |
| `/firefly role clear` | 清除本会话身份覆盖，回落到全局默认 |

## 配置项

在 AstrBot 的插件配置页面里配置。

### 基础

| 配置 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关：是否注入认知外壳 |

### 注入 `inject`

| 配置 | 默认 | 说明 |
|---|---|---|
| `max_tokens` | `1500` | 外壳整体 token 预算 |
| `tier1_reserved` | `830` | 常驻块（Tier1 人格 + 动态状态 + XML 包装）预留预算，这部分不参与按需资料的分配 |
| `max_on_demand` | `5` | 单次最多激活几条按需资料 |
| `enabled_sessions` | `[]` | 限定生效的会话（留空=全部生效） |

### 路由 `router`

| 配置 | 默认 | 说明 |
|---|---|---|
| `use_llm` | `false` | 是否启用 LLM 语义路由（更准但更慢、更贵） |
| `llm_timeout_seconds` | `3.0` | LLM 路由超时 |
| `fallback_to_keyword` | `true` | LLM 路由失败时降级到关键词 |
| `cache_enabled` | `true` | 路由结果缓存 |

### 状态 `state`

| 配置 | 默认 | 说明 |
|---|---|---|
| `persist` | `true` | 是否持久化动态状态到磁盘 |
| `decay_hours` | `0.0` | 硬性回落阈值（0=关闭，由心情半衰期自然衰减） |
| `max_topics` | `5` | 保留的最近话题条数 |

### 激活惯性 `active_context`

| 配置 | 默认 | 说明 |
|---|---|---|
| `default_skill_ttl` | `4` | 技能类资料激活后保持的轮数 |
| `default_lore_ttl` | `2` | 世界观类保持轮数 |
| `default_narrative_ttl` | `6` | 叙事类保持轮数 |
| `strength_decay_per_turn` | `0.2` | 每轮强度衰减 |
| `min_strength` | `0.3` | 强度最低保留值 |

> 三个 `default_*_ttl` 在**加载资料时**读取，因此改完配置需要重载一次资料
> （面板「资料」页的重载按钮，或重启插件）才会作用于已有条目；
> 资料文件 front-matter 里显式写的 `default_ttl` 始终优先于这三项。

### 主动消息 `proactive`

| 配置 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | 是否启用主动消息 |
| `tick_interval_seconds` | `120` | 后台评估间隔 |
| `min_contact_gap_minutes` | `30` | 距上次接触的最短静默 |
| `min_proactive_interval_minutes` | `60` | 两次主动的最小间隔 |
| `max_unanswered` | `4` | 连续未回复上限 |
| `max_per_day` | `6` | 每日上限 |
| `max_sends_per_tick` | `1` | 单次评估最多发几条 |
| `silence_hours` | `6` | 静默多久后开始「想念」 |
| `quiet_hours` | `1-7` | 免打扰时段 |
| `startup_grace_seconds` | `120` | 启动宽限期 |
| `sessions` | `[]` | 限定生效的会话（留空=全部生效） |

### 用户角色 `user_role`

| 配置 | 默认 | 说明 |
|---|---|---|
| `user_profile_max_tokens` | `600` | 用户身份块的长度上限（token）。身份块常驻且不参与裁剪，超限时只截断自身 |

## 常见问题

**Q：装上了但感觉角色没什么变化？**
A：先确认 AstrBot 的默认人格里已经确立了这个角色（例如以"你是XX"开头），再检查 `/firefly status` 与调试面板是否出现注入记录。若没有记录，检查 `enabled` 与会话白名单。

**Q：角色偶尔"出戏"、说话像通用助手？**
A：常见原因有三：① 该轮没有激活任何按需资料，她手上没有素材；② 该轮还在调用工具（工具描述会占用注意力）；③ 模型本身角色保持力较弱。可尝试把关键资料设为常驻、把 `max_on_demand` 调大、或换更强的模型。

**Q：主动消息一直没发？**
A：默认就是**关闭**的。先 `/firefly proactive on`，再用 `/firefly proactive status` 看每个会话卡在哪道闸门（常见是"距上次接触太近"或"未回复到上限"）。也可以 `/firefly proactive now` 立即测试。

**Q：改完 `role/` 里的资料不生效？**
A：在调试面板的「资料浏览」里保存会自动重载；如果是用编辑器手动改的文件，执行 `/firefly reload`。

**Q：会消耗很多 token 吗？**
A：核心人格常驻，其余按需。用 `inject.max_tokens` 控制上限，用 `max_on_demand` 控制单次激活数量。关掉不必要的常驻条目效果最明显。

**Q：定时提醒会带人设吗？**
A：会（需 AstrBot 具备内置任务系统）。任务执行时插件会把外壳注入；若钩子不可用会自动降级。

**Q：我的角色资料会丢吗？**
A：`role/` 是插件目录内的文件，随插件走；动态状态在 `data/plugin_data/` 下，重置会话用 `/firefly reset`，不会影响角色资料。

## 架构约束（贡献代码前必读）

插件分两层：`core/` 是纯逻辑（不依赖 AstrBot，可脱离运行与单测），`adapter/` 负责与 AstrBot 对接。
**边界由 `tests/test_architecture.py` 以可执行断言固化**，改动后会自动校验：

| # | 规则 | 校验方式 |
|---|---|---|
| 1 | `core/**` 不得 `import astrbot` | AST 扫描 core 下全部文件的绝对导入 |
| 2 | `core/` 各包的 `__init__.py` 只写 docstring，禁止 re-export | AST 检查 `__init__.py` 内无 import 语句 |
| 3 | `adapter/` 与 `main.py` 中只有 `adapter/astrbot_compat.py` 可直接 `import astrbot.core.*` | AST 扫描导入的模块名 |
| 4 | `core/` 内部模块依赖不得成环 | 解析相对/绝对导入构建依赖图后做环检测 |
| 5 | `FireflyCore` 的每个字段都必须被读取 | AST 判定 `self._core.X` / `core.X` 访问链 |

### 新增功能怎么放

- **新业务域**（例如"后台日常模拟"）：新建 `core/<域>/`（纯逻辑、可单测）+
  `adapter/<域>_runner.py`（定时循环、发送、记录），并在 `main.py` 的 `FireflyCore` 中登记**会被读取**的组件。
- **新调试面板 Tab**：新建 `adapter/api/<资源>.py`，在 `adapter/debug_api.py` 的 `register_routes` 里加一行调用。
- **禁止**把新功能追加到既有的大文件里；AstrBot 升级适配只改 `adapter/astrbot_compat.py`。

### 改完必须自检

```bash
ruff check .              # 依赖本目录的 ruff.toml，覆盖 core / adapter / tests
ruff format --check .
python -m unittest discover -s tests -t .
```

- **以上三条命令必须全部零告警 / 全绿**（`tests/` 的既有 lint 与格式债已清理完毕，此后不应再新增）。
- 涉及注入行为的改动会被 `tests/test_behavior_anchor.py` 以**逐字符比对**拦截；
  若确为有意修改，需同步更新该文件的期望值，并在提交信息中注明「锚点已更新」。
- 本目录自带 `ruff.toml`：**不要删它**。没有它时 ruff 会向上使用 AstrBot 根 `pyproject.toml`，
  而那份配置把 `tests` 排除在外，会让 `ruff check .` 跳过一个有告警的测试目录并报「All checks passed」。
  该文件的规则集镜像自上游，若上游调整规则需人工同步（文件内已注明出处）。
